# Quality Skill

This folder contains a reusable Codex skill for reviewing a specific Korean
Hugging Face Blog translation file for translation quality.

## Input

The primary input is a manifest generated by `translation-flow`.

The skill should read:

- `source.url`
- `source.title`
- `translation.file_path`
- `handoff.quality.checks`

## Output

The skill may produce:

- direct fixes for clear translation issues
- a quality review note
- a scorecard covering fidelity, fluency, terminology, formatting, and links

SEO optimization belongs to `seo-skills`.

## Tool

The deterministic baseline tool lives under `tools/`.

```bash
python skills/quality/tools/simple_quality_report.py \
  --manifest reports/pr-130/manifest.yaml \
  --target-root target-repo \
  --output reports/pr-130/quality-report.md
```

The Phase 1 deterministic hard-gate harness is:

```bash
python skills/quality/tools/translation_quality_harness.py \
  --manifest reports/pr-130/manifest.yaml \
  --target-root target-repo \
  --source source-post.md \
  --output-md reports/pr-130/quality-report.md \
  --output-json reports/pr-130/quality-report.json \
  --output-pr-comment reports/pr-130/pr-comment.md \
  --output-source-segments reports/pr-130/source-segments.jsonl \
  --output-target-segments reports/pr-130/target-segments.jsonl \
  --qe-metric heuristic \
  --metric-cache reports/pr-130/metric-cache.json \
  --style-guide skills/quality/style/hf-blog-ko-translation-guide.md \
  --style-policy skills/quality/configs/style_policy.yml \
  --fail-on-reject
```

It checks publishing-safety gates such as front matter, fenced code blocks,
inline code, links, images, environment variables, CLI flags, LaTeX, tables, and
unresolved TODO/placeholders. Noisy but useful exact-match checks such as prose
numbers, bare URLs, model IDs, and Python/API identifiers are reported as review
gates instead of deterministic hard failures. `--source` is optional when the
manifest includes `source.file_path`; when neither is present, the harness tries
`source.url`.
For Hugging Face Blog URLs, it fetches the public raw Markdown from
`huggingface/blog` first. If only HTML is available, it records
`metadata.source_format=url_html_text` and skips structural Markdown hard gates
that would be noisy against rendered HTML.

When reviewing files generated by the current translation workflow, the harness
normalizes workflow-only publishing scaffolding before source/target comparison:
the `> Source:` line, generated TOC block, Korean translation notice, review
instruction comment, and heading anchors such as `{#section-1}` are ignored for
hard-gate comparison while the raw target hash is still recorded in metadata.

Phase 2 also adds block-level text segments, source hash stale detection,
glossary validation from `glossary/*.tsv`, language/length/duplicate checks,
and an optional translation memory lookup via `--translation-memory`.

Phase 3 adds automatic metric triage:

- `--qe-metric off|heuristic|cometkiwi`: pluggable reference-free QE metric.
  `cometkiwi` falls back to the heuristic provider when the optional model
  dependency is unavailable.
- `--disable-embedding-similarity`: turns off embedding-similarity outlier
  checks.
- `--enable-chrf --reference approved.md`: computes chrF for regression checks
  when an approved Korean reference exists.
- `--metric-cache path.json`: caches metric results by source/target segment
  hash so repeated runs are stable and cheap.

Style-guide evaluation is enabled by default:

- `--style-guide path.md`: uses the Korean HF Blog localization guide as the
  human-readable standard.
- `--style-policy path.yml`: records the policy version and deterministic rule
  set used for style validators.
- `--disable-style-guide`: turns off style-guide validators when only hard
  gates or metric triage should run.

Style-guide findings are reported with `guide_rule` and `guide_section` fields
in JSON and a "Style Guide Findings" table in Markdown.
